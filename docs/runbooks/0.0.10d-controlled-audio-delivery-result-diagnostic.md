## Exactly-once rule

The diagnostic child executes once.

After any result:

- do not rerun;
- do not use another endpoint;
- do not widen timing or buffers;
- do not run the ordinary audio helper, tone probe, decoded-slice probe, or paired verification;
- preserve the generated external diagnostic or sanitized failure record.

## Expected diagnostic interpretation

The diagnostic record contains an ordered result sequence such as:

```text
Delivery-Result-Count: 2
Delivery-Result-1: AudioDelivered
Delivery-Result-2: RetainedAudioRecoveryRequired
```

The second line is illustrative only. The actual fixed result must be taken from the produced record.

A valid diagnostic record is not an accepted audio record. It always states:

```text
External-Binary-Or-Payload-Published: False
Physical-Runs-Executed-By-This-Command: True
Audio-Acceptance-Claimed: False
```

## Operator observation

Record `Audio audible: Yes` only for clearly recognizable retained fixture audio. Noise, click, silence, or uncertainty is `Audio audible: No`.

The audible note remains separate from the diagnostic record and does not authorize paired verification.
