# 0.0.10d Controlled Audio Render Readiness Record Preflight

## Purpose

Retain and independently revalidate one successful non-physical controlled audio render readiness report before a future authorization decision.

This workflow does not run the audio render command, child capture, one-run helper, endpoint, decoder, scheduler, fixture replay, or native output. A validated readiness record still does not grant physical-run authorization.

## Retain the readiness stdout

Run `Test-ControlledWindowsPhysicalAudioRenderEvidenceReadiness.ps1` with the exact reviewed commit, inputs, future paths, and bounds described in the readiness runbook. Capture only its success stream in memory, require exit code `0`, and then write canonical UTF-8 without a BOM to a fresh repository-external review file:

```powershell
$readinessLines = & powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\Test-ControlledWindowsPhysicalAudioRenderEvidenceReadiness.ps1 `
  -ExpectedCommit '<reviewed-main-SHA>' `
  -RuntimeDirectory 'C:\path\outside-repository\ffmpeg-runtime' `
  -FixturePath 'C:\path\outside-repository\controlled-audio-fixture.mkv' `
  -VideoRecordPath 'C:\path\outside-repository\accepted-video-record.txt' `
  -RenderEvidenceRecordPath 'C:\path\outside-repository\future-completed-record.txt' `
  -TerminalRenderRecordPath 'C:\path\outside-repository\future-terminal-record.txt' `
  -FailureRecordPath 'C:\path\outside-repository\future-failure-record.txt'

if ($LASTEXITCODE -ne 0) {
  throw 'Readiness failed; do not retain or review a success record.'
}

$readinessRecordPath = 'C:\path\outside-repository\retained-readiness-record.txt'
if (Test-Path -LiteralPath $readinessRecordPath) {
  throw 'The readiness review path must be fresh.'
}

$utf8NoBom = New-Object System.Text.UTF8Encoding($false)
$canonicalText = ($readinessLines -join "`n") + "`n"
[System.IO.File]::WriteAllText($readinessRecordPath, $canonicalText, $utf8NoBom)
```

The readiness script itself remains write-free. The explicit review step above retains only its bounded path-free stdout after success.

Do not use Windows PowerShell `>` or default `Out-File` for this record because their encoding can add a BOM or otherwise make the retained file noncanonical.

## Strict canonical schema

The managed codec requires exactly 27 ordered non-empty lines with one final newline:

- exact Phase 7 header, milestone, audio kind, and `ReadyForSeparateAuthorization` result;
- lowercase 40-character validated commit;
- the runtime build expected by the reviewed code and `Runtime-Directory-Present: True`;
- the approved fixture SHA-256 and byte count;
- accepted video-record gate;
- bounded decode, delivery, packet, observation-hold, and fixed 100 ms audio-buffer values;
- fresh completed, terminal, and failure paths;
- repository-external and pairwise-distinct path claims;
- accepted runner build;
- `Readiness-Only: True`;
- `Physical-Run-Authorization-Granted: False`;
- `Physical-Runs-Executed-By-This-Command: False`;
- `Audio-Acceptance-Claimed: False`;
- `External-Binary-Or-Payload-Published: False`;
- exact footer.

CRLF input is normalized to LF before canonical reserialization. BOM, bare carriage returns, missing final newline, extra blank lines, reordered or duplicate lines, unknown content, noncanonical numbers, weakened false claims, and trailing content are rejected.

## Offline preflight command

Run the already-built controlled Windows runner with the exact reviewed identity and bounds:

```powershell
dotnet .\src\Nova.ControlledWindowsRunner\bin\Release\net10.0\Nova.ControlledWindowsRunner.dll `
  --verify-controlled-windows-audio-render-readiness-record `
  --record 'C:\path\outside-repository\retained-readiness-record.txt' `
  --expected-commit '<reviewed-main-SHA>' `
  --fixture-sha256 '32872B300286525F4EF97FEE3533E25419AC8E48BFD4BC2C4FD9545F071B1E15' `
  --max-decode-operations 128 `
  --max-delivery-operations 128 `
  --fixture-packet-bytes 65536 `
  --observation-hold-ms 1000 `
  --audio-buffer-ms 100
```

The command requires exactly one occurrence of every argument. Unknown, missing, duplicate, malformed, or out-of-range arguments are invalid configuration.

## Successful validation

Exit code `0` emits bounded review fields such as:

```text
Milestone: 0.0.10d Phase 7
Result: ReadinessReportValidated
Validated-Commit: <reviewed commit>
Expected-Runtime-Build: btbn.ffmpeg.20260721.win64.lgpl-shared
Fixture-SHA256: 32872B300286525F4EF97FEE3533E25419AC8E48BFD4BC2C4FD9545F071B1E15
Fixture-Bytes: 66939
Readiness-Report-Validated: True
Ready-For-Separate-Authorization: True
Physical-Run-Authorization-Granted: False
Physical-Runs-Executed-By-This-Command: False
Audio-Acceptance-Claimed: False
External-Binary-Or-Payload-Published: False
```

`Ready-For-Separate-Authorization: True` means only that the retained readiness report matches the reviewed inputs and canonical schema. It does not authorize the one-run helper.

The report never prints the readiness-record path, runtime path, fixture path, video-record path, future output paths, raw process output, exception text, device identity, handles, pointers, HRESULTs, packets, samples, or payload.

## Failure behavior

- exit code `1`: invalid record or identity mismatch;
- exit code `2`: invalid command configuration.

A valid canonical record with a different reviewed commit or operation bound is rejected as `IdentityMismatch` rather than reinterpreted.

## Authorization boundary

This preflight is review-only and executes no physical output. It cannot grant or renew authorization.

The historical authorization at `4abadd280ceeae310b2528b6ea62f377211b1273` remains consumed. Any future physical execution still requires a newly reviewed readiness record, final-head and post-merge CI success for the exact commit, new repository-external outcome paths, and a new explicit one-run authorization.
