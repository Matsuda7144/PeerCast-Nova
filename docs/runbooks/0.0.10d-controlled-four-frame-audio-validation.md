## Expected production operations

The audio run selects `AudioOnly` decode. It performs four separate repetitions of the existing ordinary production sequence:

1. receive exactly one decoded audio completion;
2. transfer ownership exactly once to the sole bounded scheduler;
3. reserve exactly one scheduler item;
4. apply the existing generation timing decision;
5. convert and write exactly one 1,024-sample audio frame;
6. acknowledge the reservation exactly once.

There is no aggregate payload, second queue, repeat, retry, redelivery, resampling, normalization, amplification, fade, silence insertion, fallback, device recreation, or video Present.

The four source frames total 4,096 sample frames, approximately 85.3 ms at 48 kHz. The unchanged 100 ms stream buffer has 4,800 sample frames of capacity.

## Operator observation

Answer `Audio audible: Yes` only when the retained fixture produces a clearly recognizable short synthesized sound. A click, noise-like transient, silence, or uncertainty is `Audio audible: No`.

## Terminal behavior

The first non-successful result stops the run.

- no helper rerun;
- no delivery retry;
- no second physical audio run;
- no alternate endpoint;
- no timing or buffer widening;
- no additional diagnostic probe;
- no paired verification.

If deterministic evidence is accepted but operator observation is `No`, retain both facts and stop. If deterministic evidence and operator observation are both accepted, retain the new audio record as the independent physical audio acceptance candidate; paired verification remains a separate reviewed step.
