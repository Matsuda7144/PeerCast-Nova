# 0.0.10d Audio Render Failure Record Preflight

## Purpose

Independently revalidate one retained controlled audio render failure record after capture. The command reads one bounded UTF-8 file and starts no runner, runtime, fixture replay, endpoint, PowerShell helper, or physical output.

Two separate Phase 6 schemas are supported:

- `child`: the managed child-capture boundary did not produce a canonical completed or terminal record; current captures use version 4 and canonical legacy version 2 and 3 records remain readable;
- `helper`: the outer one-run PowerShell helper failed after authorizing the external failure path and before another retained record existed.

The reviewer must specify the expected source. A valid record of the other source is rejected rather than reinterpreted.

## Commands

Child-capture failure:

```powershell
dotnet .\src\Nova.ControlledWindowsRunner\bin\Release\net10.0\Nova.ControlledWindowsRunner.dll `
  --verify-controlled-windows-audio-render-failure-record `
  --record 'C:\path\outside-repository\render-evidence-failure.txt' `
  --expected-source child
```

Helper-level failure:

```powershell
dotnet .\src\Nova.ControlledWindowsRunner\bin\Release\net10.0\Nova.ControlledWindowsRunner.dll `
  --verify-controlled-windows-audio-render-failure-record `
  --record 'C:\path\outside-repository\render-evidence-helper-failure.txt' `
  --expected-source helper
```

The command requires exactly one occurrence of each argument and rejects unknown, missing, or duplicate arguments.

## Child failure validation

The strict current child codec requires:

- the exact `PEERCAST-NOVA-CONTROLLED-WINDOWS-AUDIO-RENDER-EVIDENCE-FAILURE 4` envelope and 20-line shape;
- milestone `0.0.10d Phase 6` and kind `Audio`;
- result `RenderEvidenceRecordNotProduced`;
- consistent signed and eight-digit hexadecimal child exit values;
- consistent child-exit availability and child-process-result capture state;
- nonnegative stdout and stderr byte counts;
- exactly one `Last-Native-Audio-Stage` value from the reviewed allowlist, or `None`;
- exactly one `Controlled-Run-Result` value parsed from an exact single-line managed result, or `None`;
- no raw stdout or stderr publication;
- no canonical completed or terminal record;
- no established physical-run completion or audio acceptance;
- no external binary or payload publication.

Canonical version 3 child records retain their exact 19-line shape and are accepted with an effective controlled run result of `None`. Canonical version 2 records retain their exact 18-line shape and are accepted with both the last native audio stage and controlled run result fixed to `None`. Version 2 records cannot claim a cleanup stage.

The retained byte counts describe only the sizes of private child output. The preflight never prints that output. The retained stage is only the last exact allowlisted stage marker. The controlled run result is retained only when stdout consists of one exact canonical `Result: <reviewed enum>` line. Unknown, additional, malformed, or noncanonical stdout becomes `None`. Raw output, unknown markers, paths, and private text are not retained.

## Helper failure validation

The strict helper codec requires:

- the exact `PEERCAST-NOVA-CONTROLLED-WINDOWS-AUDIO-RENDER-EVIDENCE-HELPER-FAILURE 2` envelope;
- milestone `0.0.10d Phase 6` and kind `Audio`;
- result `HelperFailure`;
- one reviewed bounded helper phase;
- one reviewed bounded failure category;
- no completed, terminal, or sanitized child failure record already produced;
- no established physical-run completion or audio acceptance;
- no raw exception or native stderr publication;
- no external binary or payload publication.

The record contains no exception message, stack trace, command line, path, native stderr text, device identity, handle, pointer, HRESULT, packet, sample, or payload.

## Successful report

Exit code `0` reports only bounded fields such as:

```text
Result: FailureRecordValidated
Expected-Failure-Source: ChildCapture / Helper
Detected-Failure-Source: ChildCapture / Helper
Failure-Record-Validated: True
Child-Exit-Code-Available: True / False
Child-Exit-Code-Signed: <bounded integer>
Child-Exit-Code-Hex: <eight hexadecimal digits>
Stdout-Bytes: <nonnegative count>
Stderr-Bytes: <nonnegative count>
Last-Native-Audio-Stage: <reviewed stage or None>
Controlled-Run-Result: <reviewed result or None>
Child-Process-Result-Captured: True / False
Helper-Failure-Phase: <reviewed phase or None>
Helper-Failure-Category: <reviewed category or None>
Canonical-Render-Evidence-Record-Produced: False
Canonical-Terminal-Render-Record-Produced: False
Physical-Run-Completion-Established: False
Audio-Acceptance-Claimed: False
External-Binary-Or-Payload-Published: False
Physical-Runs-Executed-By-This-Command: False
```

The record path and raw failure content are not printed.

## Failure behavior

Exit code `1` means the record is malformed or belongs to the other failure source. Exit code `2` means the command arguments are invalid.

A validated failure record explains only the bounded failure boundary. It does not establish completed render evidence, a valid terminal render record, recognizable audible audio, or audio acceptance.

## Authorization boundary

This preflight is review-only and may be run without physical-output authorization because it reads an existing record and starts no playback components.

It does not authorize another physical run. The historical one-run authorization at `4abadd280ceeae310b2528b6ea62f377211b1273` remains consumed, and that command must not be rerun.
