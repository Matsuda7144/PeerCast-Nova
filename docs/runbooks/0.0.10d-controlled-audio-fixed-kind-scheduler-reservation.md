# 0.0.10d Controlled Audio Fixed-Kind Scheduler Reservation

## Purpose

Correct the controlled four-frame audio validation after the exact delivery diagnostic proved that normal A/V scheduler alternation selected and dropped video between audio deliveries.

This runbook covers implementation and merge gates only. It authorizes no physical output.

## Retained diagnosis

The diagnostic on clean main `fe427fdc6094f55ea1a1f321217eff635febf898` ran once and must not be repeated.

```text
Run-Result: DeliveryRejected
Delivery-Attempts: 2
Delivered: 1
Retained-WouldBlock: 0
Delivery-Result-1: AudioDelivered
Delivery-Result-2: VideoDropped
Audio audible: No
```

The diagnostic record is not an audio-acceptance record.

## Correction boundary

Add one scheduler option:

```text
RestrictOutputToInitialKind
```

Default:

```text
False
```

Controlled audio:

```text
MediaSelection: AudioOnly
InitialOutputKind: Audio
RestrictOutputToInitialKind: True
```

Controlled video and normal production:

```text
RestrictOutputToInitialKind: False
```

## Required behavior

Restricted mode must:

1. search only the configured initial output kind for every reservation;
2. ignore later caller A/V preference for selection;
3. avoid opposite-kind fallback;
4. return no reservation if no matching frame exists;
5. leave unmatched frames scheduler-owned;
6. preserve all existing completion, sequence, byte, overflow, reset, cancellation, and cleanup behavior.

It must not:

- consume or drop video merely to reach audio;
- add a delivery retry loop;
- re-enqueue or redeliver frames;
- change decode order or packet submission;
- alter timestamps or timing tolerances;
- change the 100 ms WASAPI buffer;
- recreate or switch devices;
- publish paths, device identities, payloads, or native handles.

## Automated validation

Run the repository routine gate on the final PR head:

```text
restore
Release build with analyzers and warnings as errors
focused scheduler restriction tests
controlled lifecycle option tests
full solution tests
format verification
```

Required focused assertions:

- consecutive restricted reservations both return audio while video remains queued;
- restricted audio does not fall back when only video is queued;
- unrestricted selection still uses initial preference once and caller preference afterward;
- unrestricted selection still falls back to the opposite kind;
- controlled audio enables restriction;
- controlled video and default production disable restriction.
