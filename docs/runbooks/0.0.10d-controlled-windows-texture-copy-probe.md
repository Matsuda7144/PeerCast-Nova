# 0.0.10d Controlled Windows Texture-copy Probe

## Purpose

Determine whether the black-output failure remains after correcting the shared `ID3D11DeviceContext` COM vtable order. This probe creates an exact BGRA texture, copies it to swap-chain back buffer 0, and presents once.

## Preconditions

- Windows 11.
- Clean `main` checked out at the explicitly approved commit.
- A new repository-external record path.
- Audio and paired verification remain unexecuted.

No FFmpeg runtime or media fixture is required.

## Corrected rerun history

The first physical comparison attempt from main `c24db4d7f35c040113b667996097838a3a883186` terminated before canonical record creation with access violation `0xC0000005` at `ID3D11DeviceContext.CopyResource`. No visibility result was recorded.

The second attempt from main `b8eea92fd3ebc5f25072e6fa16cf8d51268c222a`, after adding `PreserveSig`, terminated at the same boundary with the same access violation. This disproved a return-signature-only explanation.

The shared root cause was a two-slot vtable omission in both Nova `ID3D11DeviceContext` declarations: `OMSetBlendState` and `OMSetDepthStencilState` were missing before `SOSetTargets`. The declared probe `CopyResource` therefore invoked `RSSetScissorRects`; the declared production `UpdateSubresource` invoked `CopySubresourceRegion`.

Run this helper again only from the explicitly approved merged main commit containing the official method-order correction.

The corrected attempt remains exactly one probe run with:

- one new repository-external record path;
- the default 3,000 ms observation hold;
- no FFmpeg runtime or media fixture;
- no retry, second Present, fallback, audio run, or paired verification.

If the helper exits nonzero or the process terminates before a canonical record is completed, stop immediately and report the first terminal boundary. Do not ask for or record operator visibility.

## Command

```powershell

  -ExpectedCommit <approved-main-sha> `
  -RecordPath '<new-external-record-path>'
```

The helper restores and builds the dedicated controlled Windows runner, performs exactly one texture-copy probe, retains the canonical record externally, and rechecks that Git remains clean.

## Operator observation

Ask for operator observation only when the canonical record states `Result: Completed`.

The expected pattern is:

- upper left: red;
- upper right: green;
- lower left: blue;
- lower right: white.

Record `Texture-copy pattern visible: Yes` only when all four regions are recognizable. A black window or unrecognizable output is `No`.

## Interpretation

- `Yes`: the corrected D3D11 texture upload, swap chain, and Win32 presentation path work; next validate the production direct `UpdateSubresource` path with the known-pattern probe.
- `No`: the failure remains below the corrected texture-copy upload in a shared D3D11／DXGI／Win32 presentation boundary.
- nonzero deterministic result or fatal termination: diagnose the first fixed boundary and do not interpret visibility.

Do not run audio or paired verification after this probe until recognizable production video output is established.
