# 0.0.10d Controlled Windows Texture-copy Probe

## Purpose

Determine whether the black-output failure is specific to the production direct `UpdateSubresource` upload. This probe creates an exact BGRA texture, copies it to swap-chain back buffer 0, and presents once.

## Preconditions

- Windows 11.
- Clean `main` checked out at the explicitly approved commit.
- A new repository-external record path.
- Audio and paired verification remain unexecuted.

No FFmpeg runtime or media fixture is required.

## Command

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\Run-ControlledWindowsTextureCopyProbe.ps1 `
  -ExpectedCommit <approved-main-sha> `
  -RecordPath '<new-external-record-path>'
```

The helper restores and builds the dedicated controlled Windows runner, performs exactly one texture-copy probe, retains the canonical record externally, and rechecks that Git remains clean.

## Operator observation

The expected pattern is:

- upper left: red;
- upper right: green;
- lower left: blue;
- lower right: white.

Record `Texture-copy pattern visible: Yes` only when all four regions are recognizable. A black window or unrecognizable output is `No`.

## Interpretation

- `Yes`: the common swap-chain／window path works and the production direct `UpdateSubresource` upload is isolated as the failing boundary.
- `No`: the failure remains in a lower shared D3D11／DXGI／Win32 presentation boundary.
- nonzero deterministic result: diagnose the first fixed result and do not interpret visibility.

Do not run audio or paired verification after this probe until the black-output boundary is resolved.
