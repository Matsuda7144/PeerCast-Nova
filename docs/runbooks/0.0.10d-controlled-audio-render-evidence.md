- ordinary helper: three attempts, two deliveries, noise-like unrecognizable audio;
- exact delivery diagnostic: four `AudioDelivered` results, accepted aggregate evidence, no audible sound.

## Authorization boundary

The helper's presence does not authorize execution.

A physical run requires all of the following:

1. a separately approved newly merged `main` commit;
2. final-head and post-merge CircleCI success for that commit;
3. exact clean local `main` at the approved SHA;
4. the approved runtime, fixture, and accepted video record;
5. new unused and distinct repository-external render-evidence and failure paths;
6. explicit one-run approval.

No ordinary helper, prior delivery diagnostic, tone probe, decoded-slice probe, render-evidence helper, or paired verification may be run during implementation.

## Helper gates

Before starting the physical child, the helper requires:

- Windows;
- checked-out branch exactly `main`;
- `HEAD` exactly equal to `ExpectedCommit`;
- a clean tracked and untracked working tree;
- repository-external runtime, fixture, video record, render-evidence record, and failure record paths;
- a retained fixture of exactly `66,939` bytes and the approved SHA-256;
- fresh, distinct render-evidence and failure paths;
- an accepted canonical video record.

Native `git` and `dotnet` stdout/stderr are redirected to private temporary files and deleted after each command. Native execution temporarily uses `ErrorActionPreference = Continue` only inside that boundary and restores the prior value immediately. Raw native stderr is never published or retained. Only explicitly required canonical stdout is parsed.

After the child exits, the helper accepts only one strict 26-line record containing:

```text
Kind: Audio
Result: Completed
Evidence: Accepted
Delivery-Attempts: 4
Delivered: 4
Retained-WouldBlock: 0
Audio-Buffer-Milliseconds: 100
Runner-State: Stopped
Lifecycle-State: Disposed
Borrowed-Window-Preserved: True
Borrowed-Dispatcher-Preserved: True
Physical-Runs-Executed-By-This-Command: True
Audio-Acceptance-Claimed: False
External-Binary-Or-Payload-Published: False
```

The record also requires hold-start, pre-cleanup, and post-stop checkpoint lines. The strict managed codec validates the fixed delivery observations, fixed WASAPI write observations, native aggregate totals, overflow state, Start state, and pre-Stop query.

## Failure behavior

Any failed child, invalid UTF-8 output, malformed record, identity mismatch, path contradiction, or integration failure is terminal.

- no automatic retry;
- no helper rerun;
- no raw stdout or stderr publication;
- no alternate endpoint;
- no timing, buffer, fixture, or operation-bound change;
- no additional probe;
- no paired verification.

When available, a sanitized child failure record retains only the child exit code and stdout/stderr byte counts. It explicitly states that raw output was not published, physical completion was not established, and audio acceptance was not claimed.

After the external failure path passes every existing path gate, any terminal helper failure that has produced neither a canonical render-evidence record nor a sanitized child failure record atomically retains a separate bounded helper-failure record. This applies to both controlled validation failures and unexpected PowerShell/helper exceptions.

```text
Result: HelperFailure
Failure-Phase: <bounded helper phase>
Failure-Category: <ValidationFailure or bounded exception category>
Canonical-Render-Evidence-Record-Produced: False
Sanitized-Child-Failure-Record-Produced: False
Physical-Run-Completion-Established: False
Raw-Exception-Published: False
Raw-Native-Stderr-Published: False
Audio-Acceptance-Claimed: False
External-Binary-Or-Payload-Published: False
```

Validation failures are identified with an internal exception marker rather than matching arbitrary exception-message prefixes. The marker and exception category are resolved through the complete `InnerException` chain so Windows PowerShell wrapping does not erase their identity.

The record does not contain exception messages, stack traces, command lines, local paths, native stderr text, device identity, handles, pointers, HRESULTs, payloads, or samples. If failure happens before the external failure path is authorized, only the same bounded phase/category is written to stderr and no file is created.

A helper-failure record does not establish whether the physical child started or completed. It exists only to identify the last helper boundary reached without exposing raw process information.
