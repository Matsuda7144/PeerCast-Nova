# 0.0.10d Controlled Audio Render Evidence

## Purpose

Capture bounded, non-perturbing evidence from the direct controlled audio production path after the contradictory retained physical results:

- ordinary helper: three attempts, two deliveries, noise-like unrecognizable audio;
- exact delivery diagnostic: four `AudioDelivered` results, accepted aggregate evidence, no audible sound.

The command records scheduler/timing decisions, WASAPI write capacity and padding, native aggregate counters, the hold-start checkpoint, the pre-cleanup checkpoint, and the one read-only pre-Stop padding checkpoint. It does not claim audio acceptance.

## Implementation status

The repository contains:

- fixed four-slot generation delivery tracing;
- fixed four-slot WASAPI render tracing;
- hold-start, pre-cleanup, and post-stop immutable checkpoints;
- sanitized native audio aggregate projection;
- a strict path-free canonical record with a 32 KiB maximum;
- a direct system-operations command without the delivery diagnostic decorator;
- a sanitized child-process capture boundary;
- `tools/Run-ControlledWindowsPhysicalAudioRenderEvidence.ps1`.

Implementation and CI do not execute physical audio.

## Authorization boundary

The helper's presence does not authorize execution.

A physical run requires all of the following:

1. a separately approved newly merged `main` commit;
2. final-head and post-merge CircleCI success for that commit;
3. exact clean local `main` at the approved SHA;
4. the approved runtime, fixture, and accepted video record;
5. new unused and distinct repository-external render-evidence and failure paths;
6. explicit one-run approval.

No ordinary helper, prior delivery diagnostic, tone probe, decoded-slice probe, render-evidence helper, or paired verification may be run during implementation.

## Command template

From the repository root, only after separate approval:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\Run-ControlledWindowsPhysicalAudioRenderEvidence.ps1 `
  -ExpectedCommit <APPROVED_MAIN_SHA> `
  -RuntimeDirectory 'C:\path\to\approved-ffmpeg-bin' `
  -FixturePath 'C:\path\to\controlled-fixture.flv' `
  -VideoRecordPath 'C:\path\outside-repository\accepted-video-record.txt' `
  -RenderEvidenceRecordPath 'C:\path\outside-repository\new-render-evidence-record.txt' `
  -FailureRecordPath 'C:\path\outside-repository\new-render-evidence-failure.txt'
```

Retain defaults unless the separately reviewed approval says otherwise:

- `MaximumDecodeOperations = 128`
- `MaximumDeliveryOperations = 128`
- `FixturePacketBytes = 65536`
- `ObservationHoldMilliseconds = 1000`

## Helper gates

Before starting the physical child, the helper requires:

- Windows;
- checked-out branch exactly `main`;
- `HEAD` exactly equal to `ExpectedCommit`;
- a clean tracked and untracked working tree;
- repository-external runtime, fixture, video record, render-evidence record, and failure record paths;
- a retained fixture of exactly `66,939` bytes and the approved SHA-256;
- fresh, distinct render-evidence and failure paths;
- an accepted canonical video record.

After the child exits, the helper accepts only one strict 26-line record containing:

```text
Kind: Audio
Result: Completed
Evidence: Accepted
Delivery-Attempts: 4
Delivered: 4
Retained-WouldBlock: 0
Audio-Buffer-Milliseconds: 100
Runner-State: Stopped
Lifecycle-State: Disposed
Borrowed-Window-Preserved: True
Borrowed-Dispatcher-Preserved: True
Physical-Runs-Executed-By-This-Command: True
Audio-Acceptance-Claimed: False
External-Binary-Or-Payload-Published: False
```

The record also requires hold-start, pre-cleanup, and post-stop checkpoint lines. The strict managed codec validates the fixed delivery observations, fixed WASAPI write observations, native aggregate totals, overflow state, Start state, and pre-Stop query.

## Failure behavior

Any failed child, invalid UTF-8 output, malformed record, identity mismatch, path contradiction, or integration failure is terminal.

- no automatic retry;
- no helper rerun;
- no raw stdout or stderr publication;
- no alternate endpoint;
- no timing, buffer, fixture, or operation-bound change;
- no additional probe;
- no paired verification.

When available, a sanitized failure record retains only the child exit code and stdout/stderr byte counts. It explicitly states that raw output was not published, physical completion was not established, and audio acceptance was not claimed.

## Operator observation

After a successful canonical record, answer separately:

```text
Audio audible: Yes / No
```

`Yes` requires clearly recognizable retained-fixture sound. A click, noise-like transient, silence, or uncertainty is `No`.

The technical record and operator observation remain separate evidence. Regardless of the result, do not rerun the command until the retained record and observation are reviewed.
