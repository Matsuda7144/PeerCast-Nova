# 0.0.10d Terminal Render Record Preflight

## Purpose

Independently revalidate one retained controlled audio terminal render record after capture. This command reads one bounded file and executes no runner, runtime, fixture replay, endpoint, or physical output.

A validated terminal record remains incomplete technical evidence. It does not establish completed render evidence, physical-run completion, audible audio, or audio acceptance.

## Command

Run the already-built controlled Windows runner with the exact values approved for the retained record:

```powershell
dotnet .\src\Nova.ControlledWindowsRunner\bin\Release\net10.0\Nova.ControlledWindowsRunner.dll `
  --verify-controlled-windows-audio-terminal-render-record `
  --record 'C:\path\outside-repository\terminal-render-record.txt' `
  --fixture-sha256 '32872B300286525F4EF97FEE3533E25419AC8E48BFD4BC2C4FD9545F071B1E15' `
  --observation-hold-ms 1000 `
  --audio-buffer-ms 100
```

The command requires exactly one occurrence of each argument and rejects unknown, missing, or duplicate arguments.

## Successful validation

Exit code `0` requires:

- strict canonical terminal codec acceptance;
- exact runtime build embedded in the codec;
- exact fixture SHA-256 supplied by the reviewer;
- exact observation-hold duration supplied by the reviewer;
- exact audio-buffer duration supplied by the reviewer;
- one reviewed terminal result;
- `PhysicalRunStarted = true`;
- `PhysicalRunCompleted = false`;
- `CompletedRenderEvidenceEstablished = false`;
- `AudioAcceptanceClaimed = false`;
- `ExternalBinaryOrPayloadPublished = false`.

The bounded report contains fields such as:

```text
Result: TerminalRecordValidated
Terminal-Result: <reviewed terminal result>
Terminal-Record-Validated: True
Physical-Run-Started-Established: True
Physical-Run-Completion-Established: False
Completed-Render-Evidence-Established: False
Audio-Acceptance-Claimed: False
External-Binary-Or-Payload-Published: False
Physical-Runs-Executed-By-This-Command: False
```

The record path and canonical JSON payload are not printed.

## Failure behavior

Exit code `1` means the record was malformed, was not a terminal record, or did not match the supplied fixture or duration identity. Exit code `2` means the command arguments were invalid.

Failure reports do not print the path, JSON payload, exception text, device identity, handles, pointers, HRESULTs, packets, samples, or raw process output.

## Authorization boundary

This preflight is review-only and may be run without physical-output authorization because it reads an existing record and starts no playback components.

It does not authorize another physical run. The historical one-run authorization at `4abadd280ceeae310b2528b6ea62f377211b1273` remains consumed, and that command must not be rerun.
