# 0.0.10d Completed Render Evidence Preflight

## Purpose

Independently revalidate one retained completed controlled audio render-evidence record after capture. This command reads one bounded file and executes no runner, runtime, fixture replay, endpoint, or physical output.

A validated record establishes that the retained technical record satisfies the completed render-evidence contract. It does not establish recognizable audible audio and does not make an audio-acceptance claim.

## Command

Run the already-built controlled Windows runner with the exact values approved for the retained record:

```powershell
dotnet .\src\Nova.ControlledWindowsRunner\bin\Release\net10.0\Nova.ControlledWindowsRunner.dll `
  --verify-controlled-windows-audio-render-evidence-record `
  --record 'C:\path\outside-repository\completed-render-evidence-record.txt' `
  --fixture-sha256 '32872B300286525F4EF97FEE3533E25419AC8E48BFD4BC2C4FD9545F071B1E15' `
  --observation-hold-ms 1000 `
  --audio-buffer-ms 100
```

The command requires exactly one occurrence of each argument and rejects unknown, missing, or duplicate arguments.

## Successful validation

Exit code `0` requires:

- strict canonical completed render-evidence codec acceptance;
- exact runtime build embedded in the codec;
- exact fixture SHA-256 supplied by the reviewer;
- exact observation-hold duration supplied by the reviewer;
- exact audio-buffer duration supplied by the reviewer;
- `Result = Completed` and `Evidence = Accepted`;
- four delivery attempts and four delivered frames;
- stopped runner and disposed lifecycle;
- valid hold-start, pre-cleanup, and post-stop checkpoint evidence;
- `PhysicalRunsExecutedByThisCommand = true` in the retained capture record;
- `AudioAcceptanceClaimed = false`;
- `ExternalBinaryOrPayloadPublished = false`.

The bounded report contains fields such as:

```text
Result: RenderEvidenceRecordValidated
Record-Result: Completed
Evidence: Accepted
Render-Evidence-Record-Validated: True
Captured-Physical-Run-Completion-Established: True
Completed-Render-Evidence-Established: True
Audio-Acceptance-Claimed: False
External-Binary-Or-Payload-Published: False
Physical-Runs-Executed-By-This-Command: False
```

`Captured-Physical-Run-Completion-Established: True` describes the retained capture record. `Physical-Runs-Executed-By-This-Command: False` describes this offline preflight command.

The record path and hold-start, pre-cleanup, and post-stop checkpoint payloads are not printed.

## Failure behavior

Exit code `1` means the record was malformed, was not a completed render-evidence record, or did not match the supplied fixture or duration identity. Exit code `2` means the command arguments were invalid.

Failure reports do not print the path, checkpoint payloads, exception text, device identity, handles, pointers, HRESULTs, packets, samples, or raw process output.

## Authorization boundary

This preflight is review-only and may be run without physical-output authorization because it reads an existing record and starts no playback components.

It does not authorize another physical run. The historical one-run authorization at `4abadd280ceeae310b2528b6ea62f377211b1273` remains consumed, and that command must not be rerun.
