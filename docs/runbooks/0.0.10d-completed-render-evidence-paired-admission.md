# 0.0.10d Completed Render Evidence Paired Admission

## Purpose

Independently admit the retained accepted video record and one strict completed
audio render-evidence record. This command reads two bounded text files. It
starts no runner, runtime, fixture replay, endpoint, decoder, scheduler, or
physical output.

## Command

Run the controlled Windows runner built from the reviewed final main:

```powershell
dotnet .\src\Nova.ControlledWindowsRunner\bin\Release\net10.0\Nova.ControlledWindowsRunner.dll `
  --verify-controlled-windows-run-records `
  --video-record 'C:\path\outside-repository\accepted-video-record.txt' `
  --audio-record 'C:\path\outside-repository\completed-audio-render-evidence-record.txt' `
  --fixture-sha256 '32872B300286525F4EF97FEE3533E25419AC8E48BFD4BC2C4FD9545F071B1E15'
```

The video record must use the canonical physical-run record codec. The audio
record may use the compatible legacy physical-run record codec or the current
strict completed audio render-evidence codec. Terminal and failure records are
not accepted.

Exit code `0` reports:

Hash both input files before and after verification and require them to remain
unchanged. The report never prints either path or any checkpoint payload.

## Failure and authorization boundary

Any malformed record, wrong kind, runtime or fixture mismatch, non-completed
evidence, cleanup contradiction, terminal record, or duplicate kind fails
closed. Do not reinterpret a rejection or create a synthetic legacy record.

This offline verification requires no physical-output authorization. It grants
no readiness or physical-run authorization and must not be followed by a
physical rerun.
