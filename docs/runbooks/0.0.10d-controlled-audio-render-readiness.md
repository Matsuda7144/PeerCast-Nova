# 0.0.10d Controlled Audio Render Readiness Preflight

## Purpose

Validate the repository, retained inputs, future output paths, runner build, and accepted video gate before requesting a separate one-run physical audio authorization.

This readiness script is deliberately separate from `Run-ControlledWindowsPhysicalAudioRenderEvidence.ps1`. It cannot invoke the render-evidence capture command, the direct physical command, an ordinary helper, a delivery diagnostic, a tone probe, a decoded-slice probe, or paired verification.

A successful readiness report is not physical-output authorization.

## Command

From a clean `main` checkout on Windows, provide the exact commit being reviewed and repository-external inputs and future output paths:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\Test-ControlledWindowsPhysicalAudioRenderEvidenceReadiness.ps1 `
  -ExpectedCommit '<reviewed-40-character-main-SHA>' `
  -RuntimeDirectory 'C:\path\outside-repository\ffmpeg-runtime' `
  -FixturePath 'C:\path\outside-repository\controlled-audio-fixture.mkv' `
  -VideoRecordPath 'C:\path\outside-repository\accepted-video-record.txt' `
  -RenderEvidenceRecordPath 'C:\path\outside-repository\future-completed-record.txt' `
  -TerminalRenderRecordPath 'C:\path\outside-repository\future-terminal-record.txt' `
  -FailureRecordPath 'C:\path\outside-repository\future-failure-record.txt'
```

Optional bounds default to the one-run helper values:

- maximum decode operations: `128`;
- maximum delivery operations: `128`;
- fixture packet bytes: `65536`;
- observation hold: `1000 ms`;
- audio buffer: fixed at `100 ms`.

## Readiness gates

The script requires:

- Windows;
- the current directory to resolve to the PeerCast Nova repository;
- checked-out branch `main`;
- `HEAD` exactly equal to `ExpectedCommit`;
- a clean tracked and untracked working tree before and after validation;
- an existing repository-external runtime directory;
- the retained controlled fixture with byte count `66939` and SHA-256 `32872B300286525F4EF97FEE3533E25419AC8E48BFD4BC2C4FD9545F071B1E15`;
- an existing repository-external accepted video record;
- fresh repository-external completed, terminal, and failure record paths;
- existing parent directories for all three future output paths;
- pairwise-distinct future output paths;
- successful solution restore and controlled-runner Release build;
- successful managed video record preflight with no physical run.

The script verifies that the runtime directory is present and records the build identity expected by the reviewed code. It does not load the supplied runtime directory or claim that its native contents were validated; that remains part of the separately authorized physical command boundary.

Native command stdout and stderr are redirected to private temporary files and deleted. Unexpected exceptions are replaced with a bounded generic readiness failure.

## Failure behavior

Exit code `1` means a readiness gate failed. A reviewed validation failure prints only a bounded category message. An unexpected failure prints only:

```text
Controlled render readiness rejected: unexpected readiness failure.
Physical runs executed by this command: No
Readiness does not authorize physical execution.
```

The script creates no output record and does not create missing directories.

## Authorization boundary

A successful readiness report means only that the reviewed local environment is prepared for a later authorization decision. It does not grant that authorization and does not permit invocation of the one-run helper.

The historical authorization used at `4abadd280ceeae310b2528b6ea62f377211b1273` remains consumed. That command and the earlier ordinary, exact-result, delivery-diagnostic, tone, decoded-slice, and paired commands must not be rerun.

Any future physical execution still requires:

1. a separately merged commit;
2. final-head and post-merge CircleCI success;
3. new repository-external completed, terminal, and failure paths;
4. a successful readiness report for the exact reviewed commit and parameters;
5. a new explicit one-run authorization.
